# Animated Clothing (Idle Figure Animation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make animated clothing (hats, hair, head/face/waist accessories, some jackets) play their frame loop while an avatar stands idle, by backporting idle figure-part animation onto `@nitrots/nitro-renderer@1.6.6`.

**Architecture:** Two surgical additions to the vendored renderer, shipped as an expanded yarn patch. (1) In `AvatarImageCache.getImageContainer`, after `AvatarStructure.getParts` builds the per-direction part containers, probe the loaded asset library for how many frames each clothing part's current posture has and, when >1, extend that container's frame array so the existing `frameCount % frames.length` cycling plays it. (2) Track a "this figure has an animated part" flag on the cache and OR it into `AvatarImage.isAnimating()`, so `AvatarVisualization` keeps ticking the frame counter and invalidating the composite for idle avatars.

**Tech Stack:** TypeScript, Yarn 3 (`yarn patch` / `patch-commit`), Vite, PixiJS, the `nitro-react` client submodule (`client/`, branch `pixelrp`), `docker/nitro/build-client.sh`.

## Global Constraints

- **Renderer version stays `1.6.6`.** The emulator only accepts the `NITRO-1-6-6` hello string derived from `NitroVersion.RENDERER_VERSION`. Do not bump the renderer package version or touch the emulator revision. (Verbatim source of truth: `docker/nitro/README.md`.)
- **Delivery is a yarn patch** on `@nitrots/nitro-renderer@npm:1.6.6`, extending the existing `client/.yarn/patches/@nitrots-nitro-renderer-npm-1.6.6-c15ae4be91.patch`. No fork, no new dependency.
- **No asset, figuredata, or gamedata changes.** The frames already exist in the `.nitro` bundles (1,217 of ~2,958 figure bundles carry idle-posture frames).
- **No new gamedata file.** Frame counts are derived from the loaded asset library at runtime.
- **Build only via `docker/nitro/build-client.sh`** (`--prod` for the prod handshake). Never hand-edit `nitro/client/` output.
- **Verification is in-game / manual**, per the user's standing preference (memory `pixelrp-manual-ingame-testing`) — the vendored renderer has no unit-test harness. Where a pure heuristic can be checked offline (frame detection), a standalone Node probe is used; the runtime rendering is confirmed in-game.

## Task 1: Offline frame-detection probe (ground truth)

Establishes, with a re-runnable script, exactly which bundles are animated and the frame grammar the renderer patch will rely on. This is the "test" for the detection heuristic.

**Files:**
- Create: `docs/superpowers/plans/tools/detect-animated-figures.mjs`

**Interfaces:**
- Produces: a documented rule — *a figure part is idle-animated iff, for an idle-posture action in `{std, sit, lay}`, an asset named `<scale>_<action>_<partType>_<partId>_<dir>_1` exists.* Task 3 implements this same rule at runtime.

- [ ] **Step 1: Write the probe script**

```javascript
// docs/superpowers/plans/tools/detect-animated-figures.mjs
// Usage: node detect-animated-figures.mjs <path-to-nitro/assets/bundled/figure> [name-substring]
import { readFileSync, readdirSync } from 'node:fs';
import { join } from 'node:path';
import { inflateSync } from 'node:zlib';

function parseNitro(buf) {
    let off = 0;
    const count = buf.readUInt16BE(off); off += 2;
    const files = {};
    for (let i = 0; i < count; i++) {
        const nlen = buf.readUInt16BE(off); off += 2;
        const name = buf.toString('utf8', off, off + nlen); off += nlen;
        const dlen = buf.readInt32BE(off); off += 4;
        let blob = buf.subarray(off, off + dlen); off += dlen;
        try { blob = inflateSync(blob); } catch { /* leave raw */ }
        files[name] = blob;
    }
    return files;
}

const dir = process.argv[2];
const filter = process.argv[3] || '';
// asset grammar: <scale>_<action>_<parttype>_<id>_<direction>_<frame>
const RE = /^[a-z]+_([a-z]+)_([a-z]+)_(\d+)_(\d+)_(\d+)$/;
const IDLE = new Set(['std', 'sit', 'lay']);

let animated = 0, total = 0;
for (const f of readdirSync(dir)) {
    if (!f.endsWith('.nitro') || !f.includes(filter)) continue;
    total++;
    const files = parseNitro(readFileSync(join(dir, f)));
    let manifest = null;
    for (const [n, b] of Object.entries(files)) {
        if (b[0] === 0x7b) { try { manifest = JSON.parse(b.toString('utf8')); break; } catch {} }
    }
    if (!manifest?.assets) continue;
    // per (action, parttype, id, direction) max frame, restricted to idle actions
    const maxFrame = {};
    for (const key of Object.keys(manifest.assets)) {
        const m = RE.exec(key);
        if (!m) continue;
        const [, action, ptype, id, d, fr] = m;
        if (!IDLE.has(action)) continue;
        const k = `${action}|${ptype}|${id}|${d}`;
        maxFrame[k] = Math.max(maxFrame[k] ?? 0, Number(fr));
    }
    const idleAnimated = Object.values(maxFrame).some(v => v > 0);
    if (idleAnimated) { animated++; if (filter) console.log('ANIMATED', f); }
}
console.log(`idle-animated bundles: ${animated} / ${total}`);
```

- [ ] **Step 2: Add the frame-count probe helper**

Add this private method to the class:

```typescript
private getFigurePartFrameCount(assetPartDefinition: string, partType: string, partId: string, direction: number): number
{
    // Mirror renderBodyPart's flipped-direction remap so we probe the same asset names.
    let assetDirection = direction;

    if(direction === 4) assetDirection = 2;
    else if(direction === 5) assetDirection = 1;
    else if(direction === 6) assetDirection = 0;

    let count = 0;

    while(count < AvatarImageCache.MAX_FIGURE_FRAMES)
    {
        const assetName = (this._scale + '_' + assetPartDefinition + '_' + partType + '_' + partId + '_' + assetDirection + '_' + count);

        if(!this._assets.getAsset(assetName)) break;

        count++;
    }

    return count;
}
```
